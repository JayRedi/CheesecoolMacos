# 设备连接与模拟模式

## 正常启动

Release 和普通 Debug 启动均默认使用真实 HID 链路。若未发现 VID `0x1A86` / PID `0xFE01` 的 CheeseCool 设备，应用保持“设备不可用”状态，设置页会说明“未检测到真实 CheeseCool 设备；风扇控制当前不可用”。它不会静默换成模拟数据，也不会触碰 PID `0x8035` 的 DFU 设备。

连接时会选择稳定排序后的一个正常运行设备，打开传输并只发送 `PING` 确认链路。随后由 `ControlSession` 按既有策略发出 `GET_STATUS`、`SET_MODE` 与 `SET_DUTY`；控制器要求停止主机通信时，传输层不会自行恢复或发送额外流量。

## 显式模拟

开发和演练可以传递：

```text
--simulation
```

既有 `--phase2-dry-run-seconds=<seconds>` 也会自动使用模拟设备，保证演练不会访问真实 HID。模拟模式在设置页诊断区明确显示为“模拟设备”，以区分真实硬件状态。

## 诊断信息

真实 HID 模式在设置页显示匹配设备、当前选中设备、连接状态、上次命令/序列/延迟、错误文本及断连、重连计数。设备被系统移除时，连接立即清除并关闭底层传输；后续恢复仍由 `ControlSession` 的有界策略管理。

## Phase 4B 建议的硬件验证顺序

取得明确的物理设备操作许可后，先被动确认仅出现 PID `0xFE01`，再依次执行一次 `PING`、只读 `GET_STATUS`、热插拔/超时 UI 状态验证。只有在确认状态正常且获得针对写入命令的许可后，才测试单次 `SET_MODE` 与 `SET_DUTY`（0、50、100）。整个流程排除 PID `0x8035`、DFU 和固件修改。
