# Phase 3：UI 与产品打磨

## 范围与边界

本阶段仅实现 macOS 客户端体验：原生 AppKit/SwiftUI UI、菜单栏交互、设置页、原生睡眠/唤醒通知和 AppIcon。控制会话继续使用真实 SoC 温度、真实 CPU 负载和 `FakeHostDevice`；未新增真实 HID、USB、PCB、固件、DFU、刷写、OpenOCD、WCH-LinkE、守护进程、特权辅助工具或系统权限。

## 产品界面

- 菜单栏主菜单显示状态摘要及 AUTO/MANUAL/MAX 选择，随后为“设置…”和“退出 CheeseCool”。
- 真实可见指标是 SoC 温度和 CPU 负载；模拟指标是风扇 RPM 和占空比。Debug 构建会在设置状态区明确标记模拟设备数据。
- SoC 功耗不显示伪造数值，状态为“不可用”；GPU 负载状态为“当前系统不支持”。
- 主图标可按用户偏好隐藏，但当没有可用指标可见时始终自动出现，保证至少一个菜单栏访问入口。
- 设置窗口可重复激活但只创建一个实例；关闭设置窗口不会退出应用。
- 所有用户可见文案使用简体中文，技术模式值 AUTO/MANUAL/MAX、RPM、CPU、°C、%、W 保留。

## 设置与安全行为

通用页面包含登录时自动启动、默认模式、恢复上次使用模式、1/2/5 秒刷新频率和带确认的“恢复默认设置”。菜单栏页面提供主图标偏好、四个可用指标开关和确定性的上/下移排序。风扇页面用原生分段控件选择模式：

- MANUAL：滑块和百分比，`0%` 明确表示最低转速，绝不表示关闭风扇。
- AUTO：显示临时温度曲线；受限步进编辑保持曲线温度严格递增、占空比位于 0–100%。这些曲线不是最终硬件校准值。
- MAX：说明将请求设备进入专用 MAX 模式。

高级页面只暴露控制回差、升速、降速和简洁诊断状态；看门狗和失效保护保持固定。电源故障使用突出状态，温度暂不可用会说明安全保护交接，不会产生模态弹窗或通知洪泛。

## 睡眠、可访问性与外观

`NSWorkspace` 的睡眠和唤醒通知会路由到冻结的 `ControlSession` 生命周期 API。控件添加了含义明确的辅助功能标签，可通过标准键盘导航操作。界面使用系统语义色、Form、Section、Toggle、Picker、Slider 和 Stepper，适配浅色与深色外观；菜单栏不手动指定字体大小。

## AppIcon

原创主稿位于 `CheeseCool/Resources/Design/CheeseCool-AppIcon-1024.png`。它为轻银色圆角方形底座、深色风扇腔、两枚金属银叶片和一枚带克制孔洞的暖黄色芝士叶片；没有 Apple 标志、文字或游戏/RGB 风格。

`Assets.xcassets/AppIcon.appiconset` 从该主稿下采样生成标准 macOS 资源：16、16@2x、32、32@2x、128、128@2x、256、256@2x、512、512@2x。工程设置 `ASSETCATALOG_COMPILER_APPICON_NAME=AppIcon`，由 Xcode `actool` 编译并嵌入应用。

## 验证

- XCTest：70 通过，0 失败（核心 50，应用 20）。
- 覆盖菜单栏回退不变量、菜单内容、指标可见性与排序、不可用功耗/不支持 GPU、模式文案、手动 0% 语义、曲线边界、重置、单设置窗口、睡眠/唤醒路由、状态映射和 AppIcon 目录。
- Debug `CheeseCool` 构建通过，Asset Catalog 编译通过。

后续真实硬件阶段才能替换 `FakeHostDevice`，届时再移除 Debug 模拟设备标记。
